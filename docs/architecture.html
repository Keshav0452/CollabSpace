Project reference

CollabSpace architecture

A workspace and task app: a React front end, an Express API, PostgreSQL for data, and Redis with a WebSocket for live updates. This page shows how the parts fit together, what each feature does, and a script for testing it the way real users would.

How the system is put together

The browser talks to one backend process over two channels: plain HTTP for everything the user does, and a WebSocket that only receives pushes. Postgres holds all data. Redis does two small jobs.

Frontend
React, TypeScript, Vite. Server data is cached with React Query; the WebSocket just tells it to refetch.
API
Express modules per feature (auth, workspaces, projects, tasks, comments, notifications, invites) with Zod validation.
Auth
15-minute JWTs. A per-user token version lets a password change sign out every other session.
Database
PostgreSQL with SQL migrations (npm run migrate:up). Every workspace-owned row carries its workspace id.

How a live notification travels

Alice assigns a task to Carol. The request finishes after one database transaction; the rest happens in the background. Because the event is stored first, it is not lost if Redis or the server is briefly down.

Features and how to try each one

Each card says what the feature does, what to click, and what you should see. If the result differs, that is a bug to report.

Accounts and sessions

Register, log in, log out. Login and register are limited to 10 attempts per 15 minutes per IP.

Try

  1. Register at /register with a 7-character password.
  2. Register again with a valid one, then log out and back in.
  3. Open /tasks while logged out.

The short password is rejected with a clear message. Logging out sends you to /login, and so does the logged-out visit. After about 10 failed logins you get a "too many requests" error.

Workspaces

A workspace is a private area with its own members, projects and tasks. A new user with no workspace must create or join one first.

Try

  1. As a brand-new user, look at the page you land on.
  2. Create "Acme Team", then a second workspace, and switch between them.
  3. Rename one in Settings and refresh the page.

You see both "create" and "join with an invite link". Data differs per workspace, the selection survives a refresh, and the new name shows in the sidebar.

Invite links

Owners and admins create a link with an expiry (1 to 30 days) and a use limit. Only a hash is stored, so the full link is shown once.

Try

  1. Members page → create a link for 1 person → copy it.
  2. Open it in a second browser as a new user, register, and click Join.
  3. Open the same link as a third user.
  4. Create another link and revoke it, then open it.

After registering you return to the invite page, not the dashboard. The joiner appears in Members. The used-up and revoked links say "invalid, expired or revoked".

Members and roles

See everyone in the workspace, add a registered user by email, change roles, remove people.

Try

  1. Add a registered user by email; add a made-up email.
  2. As owner, make that user an admin.
  3. As the admin, try to remove another admin and the owner.

The unknown email says no registered user exists. The role dropdown appears only for the owner. The admin cannot remove admins or the owner.

Projects

Group related tasks. Projects can be archived and brought back. Deleting one keeps its tasks.

Try

  1. Create "Website relaunch"; create it again with different capitals.
  2. Add tasks to it, then click "View tasks" on the card.
  3. Archive it, then delete it.

The duplicate name is refused. The card's task count matches. Archived projects can't be picked for new tasks. After deletion the tasks remain, with no project. Members don't see archive or delete.

Tasks with several assignees

Title, description, priority, status, due date, project, and any number of assignees (up to 20).

Try

  1. Create a task and tick two people under Assignees.
  2. Change its status from the list dropdown.
  3. Untick everyone; then use "Assigned to me" as one of the assignees.
  4. Search a word from a description; create 21+ tasks to see pagination.

All names show comma-separated, or "Unassigned". Search covers the whole workspace. The page controls appear after 20 tasks, and changing a filter returns to page 1.

Comments and activity

Open a task to discuss it. A history lists every change and who made it.

Try

  1. Open a task and add a comment as one user.
  2. As another user, try to edit that comment.
  3. Change assignees, priority and due date; read the history.

Only the author sees edit and delete. The history shows entries such as "changed the assignees from A to A, B".

Notifications and live updates

Assignments, status changes and comments notify the people involved, instantly if they have the app open. You are never notified about your own actions.

Try

  1. Keep two users in side-by-side windows.
  2. Assign a task to the second user and watch their bell.
  3. Have them comment and change the status; check the first user's bell.
  4. Click a notification, then "mark all as read".

The unread count rises without a refresh. Clicking opens that task. The count drops to zero after marking all as read, and stays after a refresh.

Settings and security

Edit your name and email, change your password. A password change signs out your other sessions.

Try

  1. Log in as one user in two browsers.
  2. In one, change the password (wrong current password first).
  3. In the other, click anything.

The wrong current password is refused. The other session is sent to login. The old password fails; the new one works.

Test it as real users: a script

Run this once from start to finish. It uses four people so every role gets exercised, and every feature above appears at least once. Your ticks are remembered in this browser.

AliceOwner. Normal browser window.
BobAdmin. Incognito window.
CarolMember. A second browser or profile.
DaveNew user who arrives by invite. Another incognito window.
cd backend  && npm run migrate:up && npm run dev   # terminal 1
cd frontend && npm run dev                           # terminal 2
# open http://localhost:5173  (passwords need 8+ characters)

Each browser profile keeps its own login, which is why the four people need four separate windows. Invite links on localhost work between them because they are all on your machine.
